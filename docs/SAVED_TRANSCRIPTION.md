# Saved recording transcription

Studio → Calling setup accepts an optional xAI key. Studio → Calls → a completed recording → Transcribe sends the recording to xAI only after explicit permission and charge confirmation. The key is encrypted with the existing server vault and never returned to the browser or an MCP caller. This feature uses the documented `POST https://api.x.ai/v1/stt` multipart contract with `grok-voice-transcribe-2.0`; the file is the last form field. See https://docs.x.ai/developers/model-capabilities/audio/speech-to-text.

Only completed recordings attached to ownership-verified SignalWire calls can be processed. The backend accepts a recording ID, never an arbitrary audio URL. Downloads and responses are bounded; redirects are rejected. Audio is processed in memory, not saved as a hidden archive. SignalWire remains the audio store. The saved text, word timestamps and source are account-scoped and appear in call history, account export and the agent's next-call context. Speaker diarization labels are provider estimates, not verified participant identities.

The product limit is 30 minutes/16 MB and 20 requests/hour per account. The xAI account pays for processing. Saving a key does not test its provider permissions or credits; the first transcription verifies those in practice. A successful transcription is reused. Uncertain requests are blocked from replay; no automatic retry can create a second charge. Calling setup lists unresolved jobs. After reviewing xAI usage, the owner can explicitly resolve a failed/lost attempt and allow a new paid request; this does not undo any earlier charge. Delete a local saved transcript using `DELETE /api/studio/transcription/jobs/:id`; this does not delete the audio in SignalWire. Remove the key from Calling setup independently.

This is post-call transcription. It does not switch on real-time captions, browser audio, retroactive recording or a recording that was never captured. Existing provider-generated transcripts can still be retrieved separately. A real consenting recording and a real xAI request are required for production acceptance; the automated contract fixture does not establish recognition quality or delivery.
